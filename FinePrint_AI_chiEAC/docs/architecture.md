# Architecture and implementation decisions

The React/TypeScript dashboard works independently in deterministic browser mode, making a demo possible without credentials. Browser mode parses files with SheetJS, masks basic patterns, classifies by keywords, extracts exact spans, and retrieves passages by query-term coverage. It is not semantic RAG or an LLM simplifier. No data enters localStorage, IndexedDB, or a remote model. A backend URL at build time enables real API calls with no keys in the client.

The FastAPI service implements `/upload`, `/search`, `/analyze`, `/ask`, `/session/{id}` deletion, `/health`, and `/docs`. Upload is a LangGraph state machine: ingest → redact → classify → index. Analysis is a second LangGraph graph: extract → verify → gaps → simplify. Q&A retrieves up to five sections and uses the same verifier. States are typed and rows/items are validated with Pydantic. Session state is volatile, with an unguessable token acting as a capability. No session is discoverable through a list API.

Production options are Presidio for redaction, bge-small for embeddings, ephemeral Chroma collections per session, and Anthropic structured JSON responses parsed with Pydantic. Demo fallbacks are explicitly configured; missing production dependencies cause errors, not covert fallback. Model-backed paths are present but untested without credentials and downloaded NLP/embedding models. No tools are exposed to document-controlled instructions. System prompts are static; text is serialized under an untrusted data field.

Verification normalizes case and whitespace, accepts an exact span first, then allows fuzzy matching only at 0.95 for sufficiently long spans. A fuzzy match is downgraded and displayed using actual row text. Quote verification establishes source provenance; it does not prove the claim is entailed. That requires independent evaluation. Every rejected item becomes an uncertainty entry. Multiple fee/date values in the same section get Low badges, even when they may be legitimate separate items; this conservative behavior has false positives.

Relative calendar-day calculations need an explicit ISO date anchor and record arithmetic. Business-day dates remain unresolved without a stated holiday calendar. The demo does not resolve all natural-language dates. Dates attached to different parties must be checked by the user; role disambiguation needs model-backed evaluation.

Local textstat is pinned to 0.7.4 with setuptools below 81 because newer releases tried to download NLTK resources at runtime in this environment. Pinning removes that runtime download but creates a documented dependency-maintenance task. A model-backed simplifier retries above grade 8 at most twice and flags remaining failures. The browser demo shows source excerpts instead of claiming to generate plain-language paraphrases.

File size, row count, XLSX expanded size, concurrency, API rate, and session count are bounded. An API timeout returns a clear error; a running synchronous provider task may finish in its worker thread after that response. Production should use cancellation-aware workers and reverse-proxy body/time limits. Single-process session state means use one worker or sticky sessions; do not scale across workers without designing privacy-preserving session routing.
